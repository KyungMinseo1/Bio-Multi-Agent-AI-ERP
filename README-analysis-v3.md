# BioFlow 2 — 데이터 기반 바이오 원료 발주 ERP Workspace

기존 React/TypeScript/Vite 프로젝트를 확장했습니다. 기본 화면은 **IL-7 분할 발주 업무형 Workspace**이며, 이전 FGF-2 발표 데모는 `데이터·시연 설정 → 기존 데모 열기`에서 그대로 사용할 수 있습니다.

## 실행

검증 환경: Node.js 24.13 / npm 11.6. Node 22.12 이상 권장.

```sh
npm ci
npm run dev -- --port 5173
```

배포용 실행:

```sh
npm test
npm run build
npm run preview -- --port 4173
```

터미널이 안내하는 로컬 주소를 엽니다. 기본 미리보기 주소는 `http://127.0.0.1:4173/`입니다. 포트 충돌 시 다른 포트가 안내됩니다. Vite 서버를 유지해야 앱이 열립니다. 설치 이후에는 폰트를 포함해 로컬 번들만으로 시연하며 API 키가 필요하지 않습니다. `file://` 직접 실행 대신 HTTP 서버를 사용하세요.

## 무엇이 실제로 실행되나요?

**실제 ERP 데이터 조회·필터·산술·시계열 재고 할당·제약 검증 함수가 실행됩니다.** 작업 로그와 근거 스냅샷은 그 실행 결과로 생성합니다. Agent의 해석 문장은 계산값에서 구성하는 규칙 기반 해설입니다. **외부 LLM은 연결하지 않았으며 실제 ERP 서버·주문·결제·품질 사용 승인은 없습니다.** 브라우저 내 ERP 상태를 공유하는 업무 프로토타입입니다.

조회한 행과 열이 강조되고, 실행된 이벤트를 누르면 당시 참조 데이터·수식·결과·revision을 확인할 수 있습니다. 진행률은 타이머의 가상 백분율이 아니라 **완료된 실제 계산 작업 수 / 12**입니다. `남은 계산 모두 실행`도 나머지 함수를 실제 실행합니다.

## 화면

- **업무 대시보드**: 카드 위주 화면을 생산 조달 워크리스트·Lot 재고표 중심으로 수정. 공급안 선택과 예측 재고 차트 연동.
- **AI 분석 Workspace**: ERP 테이블 / 6-Agent 네트워크·작업 로그 / 계산 근거·의사결정 보드. 넓은 화면은 3열, 중간 화면은 2열 및 결과 하단 배치.
- **발주 검토·추천서**: 스냅샷 비교표, 구매·운송 소계와 최종 총비용 차트, 지급일 현금 한도, 분할 일정, 잔여 위험과 조치, 가상 PO 승인.
- **원료·Lot 재고**: 품질 보류와 투입 전 만료를 구분. 셀 선택 상세, CoA·제품·해제 조건. 수량·유효일 편집.
- **견적·공급 확약**: 단가·MOQ·주문배수·운송비·견적 유효일 편집, 계약·공급 확약 근거 확인.
- **생산·입고 계획**: 투입일·IL-7/IL-15 수요, 회차별 입고일·QC 대기·지급일·현금 한도 편집.
- **발주·변경 이력**: PO와 당시 납품 회차 스냅샷, 원본 불일치에 따른 재검토 상태, 실제 변경 필드 기록.
- **설정**: 계산비용·QC/QA 기간, 예산 귀속, 독립 변형, 전체 초기화 및 기존 데모.

모든 주요 업무 표에 검색, 열별 오름/내림 정렬, 상태 필터, 3/6/12행 페이지 이동, 셀 선택, CSV 및 **실제 XLSX** 내보내기가 있습니다. 선택 셀에는 키보드 Enter·방향키도 지원합니다. 필터된 전체 행을 내보내며 CSV에는 UTF-8 BOM, 인용부호 처리, 수식 삽입 방지가 적용됩니다. XLSX는 숫자 셀·헤더·필터·고정 헤더와 출처 시트를 포함합니다.

## PDF 기준과 확장 데이터

원문은 `public/references/scenario_1.pdf`에 포함했습니다. 앱의 `scenario_1.pdf 근거`에서 원문과 추가 합성 설정을 구분하며 PDF·기준 JSON을 열 수 있습니다.

권위 있는 기본 seed는 `src/erp/model.ts`의 `createSeed()`입니다. 다음 명령으로 배포용 참조 JSON을 재생성합니다.

```sh
npm run seed
```

`public/erp-seed.json`은 이 모델에서 생성한 기준 스냅샷이며 현재 사용자가 편집한 브라우저 상태와는 별개입니다.

### 원문을 그대로 반영한 기준

- 기준일 2026-10-24, 계획 범위 2026-11-30 및 이후 잔여 유효일 추적
- MAT-IL7, 동반 원료 MAT-IL15, 동일 함량 바이알 단위
- IL7-LOT-01: 2개 / QC 합격·QA 승인 / 2027-03-31
- IL7-LOT-02: 2개 / 품질 보류·QA 미승인 / 2027-03-31
- IL7-LOT-03: 2개 / QC 합격·QA 승인 / 2026-10-31
- PROD-01 11.04 / PROD-02 11.11 / PROD-03 11.18, 각 IL-7 4개
- 생산 12 + 안전 2 − 생산 가용 2 = 신규 12개
- A 단가 80만원, MOQ/배수 20/20, 20개 10.30 일괄 입고, 신규 Lot 11.30 만료
- B 단가 100만원, MOQ/배수 4/4, 4개씩 10.30·11.06·11.13 확약 입고, 신규 Lot 2027.03.31 만료
- C 단가 70만원, MOQ/배수 4/4, 업체·제품 승인은 있지만 공급 미확약. 확정 가용량에서 제외
- A/B 운송비 회당 10만원, 견적 유효일 10.27, 단일 잔여 예산 1,300만원
- QC 2일 + QA 1일: B 사용 가능 예상 11.02·11.09·11.16
- B 생산 투입 후 재고 2·2·2, A 생산 사용 후 잔여 10개와 11.30 만료 위험

### 명시적으로 추가한 합성 설정

PDF에 숫자·내용이 없는 항목은 앱과 출처 목록에서 추가 합성 설정으로 표시했습니다.

- IL-15 승인 재고 20개, 생산당 4개 수요, 안전재고 2개
- CoA/견적/계약/확약/승인 문서 ID, Lot-02 CoA 대조 미완료 보류 사유 및 해제 조건
- 합성 제조사·제품코드, 고정 함량 기호 U1/U2, 변환계수 1
- **실제 함량·공식 보관 온도는 확정하지 않았습니다.** 실물 제품 등록 전 확인 필요로 표시. 임의의 실제 제품 사양이나 질량·활성 변환을 주장하지 않습니다.
- 입고 Lot당 시험비 10만원, 바이알·일 보관비 200원, 폐기처리비 2만원/개
- C 예상 입고일 10.30, 유효일 2027.03.31, 운송비 10만원은 미확약 참고값이며 공급 계획에 포함하지 않음
- 완료일은 투입 +5일, 납품 관리일은 +8일. 원료 투입 충족만으로 고객 납기 준수를 확정하지 않음
- 예산 귀속: PROD-01 240만원 / PROD-02 430만원 / PROD-03 430만원 / 안전재고 공통 200만원 = 단일 1,300만원. 같은 예산을 생산마다 반복 적용하지 않음
- 지급일 기본값은 입고일, 지급일 현금 한도는 합성 설정. 회차 구매·운송·시험비와 계획 종료일 보관·폐기처리비를 확인
- 생산 연기일 12.09, 현금 부족 변형의 B 2회차 한도 300만원
- 분할 공급 변경·취소는 서면 동의가 필요한 합성 계약. 자동 취소·감액하지 않음

## 계산 규칙

- **가용 Lot**: QC 합격 AND QA 승인 AND 온도 적합 AND 유효일 ≥ 최초 생산 투입일
- **신규 수요**: max(0, 총 생산 IL-7 수요 + 안전재고 − 생산 가용재고)
- **발주 수량**: ceil(max(신규 수요, MOQ) / 주문배수) × 주문배수. 필요량 0이면 0개
- MOQ를 올려도 기존 확약 수량 이상의 물량을 자동 확약하지 않습니다. 주문 수량과 유효 확약량이 다르면 부적격입니다.
- **예상 사용일**: 입고 처리 완료 + QC 시작 대기 + QC 일수 + QA 일수. 모두 달력일, UTC 날짜 계산
- **생산 할당**: 날짜순 입고/생산 이벤트, 같은 날 예상 사용 가능 입고를 먼저 반영. 기존 승인 재고를 먼저 쓰는 FIFO로 PDF의 A 잔여10개를 재현
- 생산일 전에 만료된 Lot, 미확약 납품, 제품/업체 미승인, 온도 이탈·해당 Lot QA 보류는 투입에서 제외
- 부족한 생산을 이후 입고로 소급 완료 처리하지 않음. 투입별 부족량을 독립 기록
- **소계**: 구매 수량 × 단가 + 회차 수 × 운송비
- **총비용**: 소계 + 입고 Lot별 시험비 + 물리 재고 바이알·일 × 보관비 + 예상 폐기량 × 폐기처리비
- 보류·만료 Lot는 반출 전까지 보관에 포함하며 QC/QA 대기 중 입고분도 공간을 점유. 동반 원료의 실제 계획 소비도 보관량에서 차감
- 폐기 재고의 장부가액은 구매비에 이미 포함하므로 별도 위험 지표로 표시하고 총비용에 중복 가산하지 않음
- **현금 검증**: 동일 지급일 의무를 합산하고 그 날의 한도와 대조. 예산 부족과 별도 제약으로 표시
- **추천**: 품질·공급 확약·생산 수량·안전재고·예산·현금·보관 용량을 통과한 후보 중 총비용 최소. 후보가 없으면 추천 보류

기존 보류·생산 전 만료 Lot의 관리 책임은 그대로 남습니다. A의 예상 폐기10개 지표는 신규 A 구매분에서 남는 수량이며 기존 제외 Lot까지 합한 폐기 수량이 아닙니다.

## 독립 변형

`변형 시나리오` 또는 설정에서 선택하며 매번 기준 데이터에서 독립 적용합니다. 이전 추천과 PO 스냅샷은 남고 재검토 상태가 됩니다.

1. **QC 병목 +3일**: B 2회차 QC 시작 대기 3일. 사용 가능일 11.12. PROD-02 11.11에는 가용2/수요4 → 2개 부족. 추천·발주 보류. 입고일 11.05까지 조정, 승인 공급 경로 추가 확약, 정식 QC 슬롯·생산 일정 변경을 제안
2. **생산 연기**: PROD-03 12.09. A 단기 유효 Lot를 해당 생산에 쓸 수 없어 폐기 위험 확대. B 미출하 회차 변경은 계약 근거로 확인
3. **온도 이탈**: B 2회차만 QA 보류. 다른 회차나 업체 전체 차단 없음, AI 보류 해제 없음
4. **특정 Lot 품질 이슈**: 제조사·제품코드·Lot가 모두 일치한 공지만 영향 범위로 계산
5. **관련성 미확인 공지**: 자동 차단·감점 없이 추가 확인 경고
6. **현금 부족**: 예산 내 B안이더라도 2회차 지급일 현금 부족으로 승인 차단
7. **C 제품 미승인**: 공급 미확약 사유와 품질 필수조건 탈락을 분리
8. **승인 직전 변경**: 추천서 상단 버튼이 PROD-02 수요를 1개 늘림. revision과 fingerprint 불일치로 기존 추천 승인 차단

실제 변경은 테이블의 `편집`에서 단가·MOQ·수량·투입일·입고일·QC 대기를 수정해도 확인할 수 있습니다. 수량·일정을 편집하는 것으로 QA 상태나 공급 확약이 바뀌지 않습니다.

## 3–5분 시연

1. 대시보드에서 장부6 / 가용2 / 신규12 확인
2. `IL-7 발주 분석` → 행·셀 강조와 Agent 로그 관찰. 발표용은 작업별 가변 속도(발표용/기본/빠르게). 필요한 경우 `남은 계산 모두 실행`
3. 로그를 클릭해 Lot-02·03 제외 근거 확인. A MOQ20과 잔여10, A/B 소계 차이380만원, 최종 B안을 확인
4. 추천서에서 비용 소계/TCO/현금/QC 일정을 비교 → 가상 PO 등록
5. `승인 직전 수요 변경`으로 기존 추천 만료와 PO 재검토를 확인
6. Workspace → `변형 시나리오 → QC 병목 +3일` → 재분석 → PROD-02 부족·추천 보류·수정 조치 확인
7. 입고·QC/QA 테이블에서 RCPT-B-02 QC 대기를 0으로 편집 → 사용일과 생산 판정의 즉시 변경 및 옛 추천 stale 확인 → 재분석
8. 설정에서 전체 초기화로 반복

## 상태·승인 경계

- 원본 데이터 revision과 내용 fingerprint를 함께 비교합니다.
- 데이터 변경 시 실행 중 작업은 중단되고 이전 작업 로그를 새 분석에 재사용하지 않습니다.
- 각 분석의 원본·결과·이벤트를 깊은 복사로 보존합니다(최근10개).
- PO에는 당시 회차 스냅샷을 저장합니다. 원본 불일치는 자동 취소 대신 `재검토 필요`로 표시합니다.
- 승인 시 데이터/로그 revision, 원본 fingerprint, 전체 작업 완료, 적격 후보, 중복 PO를 다시 확인합니다.
- 승인해도 Lot 수량·QC/QA를 변경하지 않습니다. 실제 입고·품질 승인 프로세스는 이 MVP 범위 밖입니다.
- localStorage `bioflow-erp-v2`에 저장하며 이전 `bioflow-erp-v1`은 독립 보존합니다. 서버 데이터베이스·다중 사용자 동시성은 지원하지 않습니다.

```text
  erp.css           기존 디자인을 확장한 테이블 중심 레이아웃
```

이전 코드/데이터/테스트는 그대로 남아 있고 `App.tsx`가 신규/기존 데모를 전환합니다. 기존 사용법은 `README-legacy.md`를 참고하세요.

## 실제 LLM 연결 확장

현재는 미연결입니다. `tools.ts`에 `query_lots`, `evaluate_procurement`, `validate_recommendation`의 JSON 스키마 및 읽기 전용 실행기를 제공합니다. `interpretationSchema`와 `validateInterpretation`은 모델의 revision·선택 공급안·근거 ID가 결정론적 결과와 일치하는지 검증합니다. 모델 출력이 계산 결과를 덮어쓸 수 없습니다.

실제 연결 시 별도 서버에서 API 키와 Tool Calling·Structured Output을 처리하고, 화면에 실제 호출 모드/오류/모델 응답을 표시해야 합니다. 브라우저에 API 키를 넣지 마세요. 모델에 품질 해제·PO 등록 도구를 제공하지 않습니다. 기존 `engine.ts`의 서버 어댑터는 참고 인터페이스이며, 신규 Workspace에 API 연결을 가장하는 스위치는 없습니다.

## 검증과 한계

`QA.md`에 자동 검사와 브라우저 검증 범위를 기록했습니다. 이 앱은 합성 ERP 데이터로 동작하는 업무 프로토타입입니다. 실제 제조 제품·보관 조건·CoA·공급 계약·품질 승인·세금·지급 조건을 검증하지 않았습니다. 사용일 예측과 고객 납기 확정은 구분합니다. 고객용 운영 ERP나 규제 제조 시스템으로 사용할 수 없습니다.


## UI 3차 개선 — 큰 글씨·부서별 판단·스프레드시트

- 구매·재고/물류·생산관리·재무의 **판단 4개**를 큰 결과 영역에 표시합니다. 각 결과는 실제 견적과 계산값으로 생성합니다.
- 기준 데이터에서는 구매 A(단가), 재고 B(폐기 최소화), 생산 A(조기 확보 여유), 재무 B(총비용)를 선호합니다. QC/QA가 품질 필수조건을 확인하고 Admin이 전체 제약을 통과하는 최종 B안을 선택합니다. 다수결이 아닙니다.
- 가격·일정·재고가 달라지면 부서별 선호와 Admin 결과도 바뀝니다. 네 결과는 네 공급업체를 뜻하지 않고 서로 다른 목적을 가진 네 부서의 제안입니다.
- 작은 6개 상태 타일을 전체 폭의 부서별 결과 → QC/QA → Admin 조정 순서로 변경했습니다. 결과는 해당 분석 작업을 실행한 뒤 나타납니다.
- 표/본문 약 16px, 부서 제안 27px, Admin 결론 30px로 확대했습니다. 어두운 탐색 메뉴, 평평한 명령 영역과 목록, 선명한 구분선과 텍스트를 사용합니다. 작은 화면에서는 스크롤과 가로 스크롤로 가독성을 유지합니다.
- 표에 A/B/C 열 머리글, 행 번호, C2 같은 셀 주소, 선택 값 수식줄, 선택 셀 테두리, 시트 탭과 고정 식별 열을 추가했습니다. 실제 XLSX도 큰 글씨·행 높이·숫자 서식·격자선을 포함합니다. CSV 파일은 원래 데이터 형식을 유지합니다.
- 단순 조회는 약 0.3~0.8초, 비용·생산 검토와 최종 조정은 수 초의 서로 다른 간격으로 표시합니다. 복잡한 제약이 있으면 검토 표시 시간이 더 길어집니다. 설정의 속도는 전체 배율입니다. 이는 시연의 재생 시간이며 외부 모델의 실제 응답 시간이 아닙니다.
