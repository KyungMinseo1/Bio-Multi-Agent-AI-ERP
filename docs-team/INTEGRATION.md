## 보존·연결한 내용

- 기존 React/Vite 앱, 레거시 분석 화면, FGF-2 예시, IL-7 기준 데이터, 결정론적 계산 엔진과 3–5분 Demo 절차를 보존했습니다.
- 팀원 백엔드의 인증/역할, API, DB 모델/마이그레이션, 워커, 공급자 설정, 네 개 독립 분석과 Orchestrator, 시나리오·ERP·외부 이슈 화면을 가져와 기존 React 앱 내부의 **통합 서버 · 실제 AI** 작업공간으로 연결했습니다.
- 주 업무 원본과 서버 workspace 간 저장·불러오기·revision 확인을 추가했습니다. 최종 발주 등록은 현재 원본/견적/승인 상태를 다시 검사하고 DB 발주번호를 생성합니다. 같은 구매요청을 중복 등록할 수 없습니다.
- PDF 기준 IL-7 Demo는 로컬에서 계속 100% 실행 가능하며 실제 LLM 모드는 선택적입니다. 실제 LLM이 미설정·실패한 경우 가짜 분석을 표시하지 않습니다.
- 외부 연락, 결제, 외부 ERP 주문 전송은 제외되어 있으며, 발주 등록은 시연용 내부 DB에만 기록됩니다. 품질 보류 Lot는 서버 추천만으로 사용 승인되지 않습니다.

## 데이터·환경 경계

- `.env.example`에는 빈 자격증명 예시만 있습니다. 실자격증명, `.env`, `.runtime/`, SQLite DB, Python 가상환경은 Git 제외 대상으로 유지합니다.
- 로컬 실행기는 기존 환경값을 덮어쓰지 않으며 필요한 시연 계정 키는 `.runtime/local-demo.env`에 제한된 권한으로 생성합니다.
- 기존 IL-7 규칙 기반 분석과 팀원 시나리오 계산/LLM 검토는 목적이 다르므로 서로의 seed를 덮어쓰지 않습니다. 주 업무를 별도 시나리오로 서버에 저장하면 기존 BioFlow 계산 번들이 재실행됩니다.
- LLM provider의 API 키는 서버 환경변수로만 읽고 브라우저에 저장하지 않습니다.

## 검증

- `npm test`: 68개 통과
- `npm run build`: TypeScript 검사, 기존 계산 엔진 서버 번들, Vite 배포 번들 성공
- `npm run test:api`: 121개 통과
- 통합 로컬 서버에서 `/health`와 정적 앱 응답 확인
- 브라우저에서 구매요청 업무함 → 통합 서버 로그인 → 현재 BioFlow 업무 서버 저장(R1) → AI 병렬 검토 화면 이동 확인
- 실제 LLM 호출은 자격증명이 없어서 실행하지 않았습니다. 실제 검토 페이지는 미설정 상태를 표시하고 합성 의견을 만들지 않습니다.

## 알려진 제한

- 실 provider key가 없는 환경에서는 **실제 AI 병렬 검토**를 수행할 수 없습니다. 키가 없는 전체 Demo는 규칙 기반 기존 워크플로로 재생할 수 있습니다.
- 실제 LLM 결과 검증은 공급자 응답을 모킹하는 계약 테스트로 확인했습니다. 운영 공급자 모델별 latency·structured output 차이는 실 키를 설정한 환경에서 별도로 확인해야 합니다.
- 빌드가 성공하지만 ExcelJS 의존성으로 큰 번들 경고가 있습니다. 기존 스프레드시트 내보내기 기능 보존을 우선했습니다.
- 사용자 계정/조직 및 DB 배포는 프로토타입용이며 운영환경 보안·백업·동시 사용자 요구에 대한 별도 검토가 필요합니다.
