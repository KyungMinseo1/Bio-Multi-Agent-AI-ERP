# 시나리오 1. IL-7 분할 발주로 생산 일정 확보와 고가 원료 폐기 최소화

작성일: 2026-10-24  
관련 문서: [구현 계획](PLAN.md), [바이오 원료 조사](ERP_가상데이터_및_바이오원료_조사.md)

## 1. 배경과 목적

가상의 면역세포치료제 공정개발·파일럿 생산 기업이 T세포 배양에 사용하는 성장인자·사이토카인을 구매한다. 핵심 발주 대상은 **재조합 인간 IL-7**, 동반 원료는 **재조합 인간 IL-15**다. IL-15는 정상 승인 재고를 충분히 두어 이번 발주 논의는 IL-7에 집중한다.

IL-7과 IL-15는 실제 T세포 증식 및 CAR-T·TCR-T 세포의 체외 제조에 사용되는 제품이 있다. 다만 본 시나리오는 실제 제조공정이나 처방을 재현하지 않는다. 모든 업체·가격·수요량·일정·유효일·시험기간·승인 기록은 합성 데이터다.

핵심 질문은 다음과 같다.

> 단가가 싼 대량 구매와 단가가 높은 분할 구매 중, 품질 조건을 충족하면서 생산 일정을 지키고 총비용과 폐기를 줄이는 방법은 무엇인가?

## 2. 원료와 데이터 기준

| 항목 | 설정 |
|---|---|
| 계산 기준일 | 2026-10-24 |
| 계획 범위 | 2026-11-30까지, 잔여 원료의 유효일도 별도 추적 |
| 핵심 원료 | 재조합 인간 IL-7, 내부 품목 코드 MAT-IL7 |
| 동반 원료 | 재조합 인간 IL-15, 내부 품목 코드 MAT-IL15 |
| 구매·재고 단위 | 동일 승인 제품·동일 함량의 바이알 |
| 안전재고 | IL-7 2바이알 |
| 공급업체 | 가상의 A/B/C 업체 |
| 최종 조치 | 담당자가 대안을 선택·승인한 뒤 내부 PO 등록 |

바이알은 본 문서의 수량 표시 단위다. 실제 seed에서는 특정 제품 코드·제형·바이알당 함량·기본단위 변환계수를 고정해야 한다. 다른 함량이나 질량·활성 단위를 근거 없이 환산하지 않는다. 아래 생산당 4바이알은 구매 수요를 보여주기 위한 합성 값이며 실제 배양 투여량이 아니다.

보관 온도는 ‘성장인자이므로 냉동’으로 일괄 지정하지 않는다. 선택 제품의 공식 규격에 따라 미개봉·재구성 후 조건을 각각 등록한다. 초기 시연 재고는 미개봉으로 한정하고 재구성 후 잔량은 생산별 승인된 사용·폐기 정책을 적용한다.

## 3. 생산계획과 재고

### 3.1 생산 수요

| 생산 ID | IL-7 최초 투입일 | 필요량 | 후속 일정 관리 |
|---|---|---:|---|
| PROD-01 | 2026-11-04 | 4바이알 | 생산계획의 완료·납품 일정에 연결 |
| PROD-02 | 2026-11-11 | 4바이알 | 동일 |
| PROD-03 | 2026-11-18 | 4바이알 | 동일 |
| 합계 | — | 12바이알 | — |

이 문서의 판단 마감은 각 원료 투입일이다. 고객 납품일과 생산·완제품 확인·운송기간은 실제 seed에서 서로 맞물리게 추가한다. 미설정 상태에서는 고객 납기 충족을 확정하지 않는다. IL-15는 동일 생산계획의 수요와 안전재고를 충족하는 승인 재고를 별도로 등록한다.

### 3.2 IL-7 재고

| Lot | 잔량 | QC/QA 상태 | 유효일 | 이번 생산 가용량 |
|---|---:|---|---|---:|
| IL7-LOT-01 | 2 | 합격/승인 | 2027-03-31 | 2 |
| IL7-LOT-02 | 2 | 품질 보류/미승인 | 2027-03-31 | 0 |
| IL7-LOT-03 | 2 | 합격/승인 | 2026-10-31 | 0 |
| 합계 | 6 | — | — | 2 |

Lot-02에는 보류 사유와 해제 조건을 기록한다. 완료 근거가 없으므로 미래에 승인될 것으로 가정하지 않는다. Lot-03은 기준일에는 유효하지만 최초 투입 전에 만료된다. 보류·만료 Lot도 실제 반출 전까지 보관 공간을 사용한다.

이번 범위에는 기존 발주와 다른 생산의 예약이 없다고 가정한다. 필요한 신규 발주량은 다음과 같다.

**생산 수요 12 + 안전재고 2 − 투입일에 사용할 기존 재고 2 = 12바이알**

## 4. 공급업체 견적과 대안

모두 가상의 견적이다. A/B는 동일 제조사·동일 승인 제품을 공급하는 가상 경로로 설정하며 실제 공식 대리점이라고 주장하지 않는다. 견적 유효일은 2026-10-27까지다.

| 조건 | A: 대량 할인 | B: 분할 구매 | C: 저가 미확약 |
|---|---|---|---|
| 단가 | 800,000원 | 1,000,000원 | 700,000원 |
| MOQ/주문배수 | 20/20바이알 | 4/4바이알 | 4/4바이알 |
| 비교 수량 | 20 | 12 | 12 |
| 구매금액 | 16,000,000원 | 12,000,000원 | 8,400,000원 |
| 입고 방식 | 전량 10-30 입고 처리 완료 예정 | 4개씩 10-30, 11-06, 11-13 입고 처리 완료 예정 | 예상일만 제시, 출하 미확약 |
| 공급 확약 | 20개 출하 근거 있음 | 회차별 수량·일정 확약 있음 | 없음, 납품 실적 근거도 없음 |
| 승인 상태 | 업체·제품 승인 | 업체·제품 승인 | 업체·제품 승인은 있으나 공급 근거 부족 |
| 신규 Lot 유효일 | 2026-11-30 | 각 회차 2027-03-31 | 제시 규격은 적합하나 납품분 미확정 |

A/B의 운송비는 회당 100,000원으로 가정한다. 구매+운송 소계는 A 16,100,000원, B 12,300,000원이다. 보관비·시험비·예상 폐기비를 합산한 최종 총비용은 별도로 계산한다. 승인된 잔여 구매예산은 13,000,000원으로 두고 총비용 및 지급일별 현금 한도를 재검증한다.

C는 저렴하다는 이유로 공급 확정안처럼 추천하지 않는다. C의 제품 승인까지 미완료인 변형에서는 품질 필수조건 탈락으로 분리한다. 공급 불확실성과 품질 미승인은 서로 다른 제외·보류 사유다.

### 4.1 A의 과잉 구매와 폐기 위험

기존 가용 2 + 구매 20 − 생산 사용 12 = **10바이알 잔여**다. 단, `PLAN.md`의 FEFO를 적용하면 유효일이 빠른 A 신규 Lot에서 12개를 먼저 사용한다. 따라서 잔여 구성은 **A 신규 Lot 8개(2026-11-30 만료) + 기존 장기 유효 Lot 2개(2027-03-31 만료)**이며, 11-30까지 후속 수요가 없을 때 이번 계획의 예상 폐기는 **8개**다. 기존 재고를 먼저 쓴다는 별도 예약이 없는 상태에서 10개 전부를 11월 말 폐기로 계산하지 않는다. 안전재고 목표라고 해서 유효기간을 넘겨 사용할 수 없다.

### 4.2 B의 분할입고와 가용량

QC 2일 + QA 1일을 합성 소요일로 설정한다. 슬롯 대기가 없으면 입고 처리 완료 후 3일 뒤 사용 가능 예상이다. 실제 사용 승인은 담당자가 수행한다.

| 시점 | 사건 | 사용 가능 재고 예상 |
|---|---|---:|
| 기준일 | 기존 승인 재고 | 2 |
| 11-02 | 첫 입고 4개 QC/QA 완료 예상 | 6 |
| 11-04 | PROD-01에 4개 사용 | 2 |
| 11-09 | 두 번째 입고 4개 QC/QA 완료 예상 | 6 |
| 11-11 | PROD-02에 4개 사용 | 2 |
| 11-16 | 세 번째 입고 4개 QC/QA 완료 예상 | 6 |
| 11-18 | PROD-03에 4개 사용 | 2 |

B는 확약된 일정대로 입고되고 각 회차의 QC/QA가 예정대로 완료될 때 필요한 생산 수요를 충족하고 안전재고 2개를 유지할 것으로 계산된다. 미래 QC/QA 완료는 예측이며 현재 확정 재고와 구분한다. 분할 계약은 회차별 공급량·입고일·취소/변경 조건·운송비·납품 Lot 근거를 포함해야 한다.

## 5. 네 AI의 병렬 검토와 Orchestrator 통합 선정

| 역할 | 목표 | 검토 근거와 의견 |
|---|---|---|
| 구매 AI (`purchasing`) | 발주 담당자의 AI로 구매 조건 검토 | 할인·MOQ·분할 계약·회차별 확약 비교. 낮은 단가와 낮은 구매 총액을 구분 |
| 재고/생산계획 AI (`inventory_planning`) | 부족·폐기 최소화와 투입 일정 확보 | 장부 6개와 가용 2개 구분, 잔여량·유효일·온도별 공간, QC/QA 완료 예상과 생산 투입일을 함께 검토. 임의 감량·대체 금지 |
| 품질 검토 AI (`quality`) | QC/QA 조건과 시험·승인 일정 검토 | 업체·제품·Lot·CoA·온도 기록·시험 슬롯·추가 시험비 검토. 발주 승인은 실제 사용 승인이 아님 |
| 재무 AI (`finance`) | 총비용·예산·현금흐름 검토 | 구매·운송·보관·시험·예상 폐기 비용과 지급일 비교. 단가만으로 절감액을 산정하지 않음 |
| Orchestrator (`orchestrator`) | 전체 의견과 근거를 통합해 최적 제안 선정 | 모든 회차의 검토와 계산 검증을 연결해 추천 이유·잔여 위험을 설명하고 담당자 선택·승인을 요청 |

작은 바이알 원료이므로 냉장고 공간 부족을 주된 갈등으로 만들지 않는다. 이 시나리오의 중심은 **사용기한·품질·공급 일정·시험 부담·고가 잔량 폐기**다. 온도별 공간 검증은 기본 필수조건으로 유지한다.

### 기대 검토 흐름

1. 부족량·만료 위험과 함께 A 대량 구매, B 분할 구매, C 저가 미확약 기본 발주안을 대시보드에서 보여준다. 이 단계에는 적합·추천·순위 레이블을 붙이지 않는다.
2. 사용자가 검토를 요청하면 구매·재고/생산계획·품질·재무 AI가 같은 기본 제안들을 **동시에** 검토한다. 각 AI는 ERP 전체가 아닌 **자기 부서 담당 ERP 데이터**(구매: 공급업체·견적·발주, 재고/생산계획: Lot·수요·생산계획·보관, 품질: Lot·승인·시험 일정·이슈, 재무: 예산·견적·발주)와 공통 목표인 원료 부족 상황, 후보별 자기 역할 관련 수치만 받는다. 구매 AI의 선행 응답을 기다리지 않는다.
3. `LLM_REVIEW_ROUNDS=1`이 기본이다. `2`이면 첫 회차 네 AI의 의견 전체를 공유하고 네 AI의 병렬 검토를 한 번 더 실행한다. 이견 유무로 설정한 회차를 건너뛰지 않는다.
4. Orchestrator는 모든 회차의 구조화된 검토 결과와 후보 표(수량·비용·적격성 검증), 남은 이견만으로 적절한 제안과 우선순위를 선정한다. ERP 레코드는 받지 않고 검토 AI가 인용한 근거만 인용할 수 있으며, 별도 LLM 요약 호출이나 의견·후보 임의 절단도 없다. 계산기의 기존 정렬을 최종 순위로 대신하지 않는다. 적합한 안이 없으면 추가 확인사항을 설명한다. 최종 추천은 서버가 원본 스냅샷으로 재검증한다.
5. 담당자가 결과와 잔여 위험을 검토하고 수정 검토·선택·승인한다. 실제 발주일은 담당자 결정 전 미정이다.

`LLM_REASONING_EFFORT=low`로 네 검토 AI와 통합 AI의 실제 API 추론 강도를 낮추고 결론·핵심 비교·남은 조건 위주로 짧게 응답하도록 요청한다. 역할별 `reasoning_effort`가 우선하며 `auto`는 추론 제어를 생략해 모델 기본값을 쓴다. 지원하지 않는 서버/모델은 `auto`로 설정한다. 호출 제한 시간은 일반 검토 `LLM_TIMEOUT_SECONDS=60`, 통합 검토 `LLM_ORCHESTRATOR_TIMEOUT_SECONDS=180`이 기본이며 역할별 `timeout`(초)이 우선한다. 이 값은 응답 목표가 아닌 실패 상한이다. 설정 변경 후 API와 worker를 모두 재시작한다. 시간초과 후 자동 재시도·추가 축약·검증 우회는 하지 않는다. 이전 `admin`은 새 설정에서 `orchestrator`로 변경하고 과거 저장 기록은 원문 그대로 보존한다.

### 화면에서 구분할 의사결정 단계

1. **상황과 기본 발주안**: 장부 6개, 생산 가용 2개, 생산 수요 12개, 안전재고 2개와 조건부 추가 필요량 12개를 설명한다. A/B/C 기본안을 바로 비교하되 가격·수량·일정·예상 폐기 등 자료만 제공한다. 어느 안이 적절한지는 아직 판단하지 않는다.
2. **명시적인 병렬 AI 검토 요청**: 네 AI가 설정된 횟수만큼 검토한다. 각 회차의 입력은 동일하며 다음 회차에는 이전 회차의 전체 의견이 공유된다.
3. **Orchestrator 통합 결과**: 실제 AI 의견과 계산 재검증을 거친 결과에만 추천·적절성 판단을 표시한다. LLM 미설정·호출 실패 시 계산 후보나 가짜 의견으로 추천을 대신하지 않는다.
4. **담당자 선택·승인**: revision 변경 시 재검토, 권한·필수조건·납기·현금·예산 및 승인 직전 재검증을 유지한다. 내부 PO 등록은 외부 주문 전송이나 QC/QA 사용 승인이 아니다.

화면의 `역산 검토 기한 추정`은 첫 부족 예상일에서 유효 견적 중 가장 짧은 등록 조달기간을 뺀 참고 계산이다. 실제 발주일·선택 공급안의 확정 납기가 아니며, 공급 확약·시험 슬롯·선택 전략·계획 변경에 따라 다시 검토한다. 미래 입고와 QC/QA 완료 및 사용 가능 재고는 조건부 예측으로 표시하고 현재 승인 재고와 섞지 않는다.

## 7. ERP에 필요한 데이터와 검증

- **제품 식별**: 원료명, 제조사, 제품 코드, 제형, 함량, 등급, 사용 공정, 승인 근거. IL-7과 IL-15는 대체재로 취급하지 않는다.
- **Lot 관리**: 미개봉 유효일, QC/QA 상태, CoA 참조, 운송 온도 기록 판정, 보류 사유. 개봉·재구성을 지원할 때는 시각·승인된 사용기한·동결해동 이력을 추가한다.
- **수량 관리**: 바이알별 동일 함량과 포장 변환을 고정한다. 생산에서 일부 사용 후 남는 양의 재사용·폐기 규칙을 명시한다.
- **분할 공급**: 회차별 수량·입고 확약·예상 QC/QA 완료·유효일·일정 변경 조건을 저장한다.
- **비용 관리**: 구매·운송·보관·시험·예상 폐기를 구분한다. `PLAN.md`와 구현 비용 모델에 입고 Lot별 시험비를 별도 항목으로 포함한다.
- **예산 귀속**: 합산 13,000,000원은 세 생산의 잔여 한도 합계다. 실제 seed에서는 생산별 배분과 안전재고 비용 귀속을 정하고 같은 예산을 중복 사용하지 않는다.
- **근거 추적**: 합성 문서·메시지·전략 버전·계산 결과에 실제 ID를 부여한다. 과거 추천은 당시 스냅샷을 유지한다.

### 구현 후 확인할 정답

1. 장부 6개를 이번 생산의 가용 6개로 계산하지 않는다. 신규 필요량은 12개다.
2. A는 MOQ로 20개 구매하며, 현재 수요만 반영하면 10개가 남는다. FEFO 기준 신규 Lot 8개가 11월 말 예상 폐기이고 기존 장기 유효 Lot 2개는 유지된다.
3. B는 세 회차 모두 예정대로 승인되면 생산마다 사용 후 2개를 유지한다.
4. C의 미확약 물량은 확정 공급처럼 계산하지 않는다.
5. QC 병목 변형에서는 11-11 부족을 감지한다.
6. 비용 비교는 구매+운송 소계와 최종 총비용을 구분한다.
7. 사용자 발주 승인이 재고의 QC/QA 상태를 변경하지 않는다.
