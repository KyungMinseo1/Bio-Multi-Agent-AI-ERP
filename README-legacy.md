# BioFlow — 바이오 원료 발주 AI ERP 데모

한국어 발표용 MVP입니다. **실제 AI 호출·기업 ERP 연동·주문·결제는 없습니다.** 6개 전문 AI가 발주안을 검토하는 과정을 사전 정의된 협의로 시뮬레이션합니다. 재고 소진일, 입고일, QC 완료일, 후보 적격성, 예산과 비용은 데이터로 계산합니다.

## 실행

Node.js **22.12 이상** 권장(검증 환경: Node 24.13). 최초 설치에는 인터넷이 필요하며, 설치 후 데모의 AI 기능에는 인터넷과 API 키가 필요하지 않습니다.

```sh
npm ci
npm run dev -- --port 5173
```

터미널에 표시된 주소(기본 `http://127.0.0.1:5173`)를 엽니다. 포트가 사용 중이면 Vite가 다음 포트를 안내합니다. 실행 중인 터미널을 유지하세요.

```sh
npm test       # 데이터·날짜·후보 선정·비용 계산 테스트
npm run build # TypeScript 검사 + 배포용 정적 빌드
npm run preview -- --port 4173 # dist 로컬 미리보기
```

`dist`는 정적 호스팅 가능한 결과물입니다. 브라우저의 `file://`로 직접 여는 대신 HTTP 서버로 실행하세요. 외부 배포는 하지 않았습니다. 폰트도 번들에 포함되어 설치 이후 외부 Google Fonts 연결이 필요하지 않습니다.

## 3–5분 발표 순서

1. **대시보드 (30초)** — FGF-2 18 mg, 일평균 3 mg, 6일 후 재고 소진 알림과 생산 위험을 소개합니다.
2. **AI 협의실 (약 1분)** — `AI 발주 분석 시작`. 구매 AI의 저가 A안 제안, 생산 AI의 납기 반박, QC/QA와 재무 검토, Admin의 B안 결정을 관찰합니다. 발표를 천천히 하려면 재생 속도를 `발표용 · 12초/단계`로 선택하세요. 기본은 6초/단계입니다.
3. **추천서 (40초)** — `최종 추천서 확인` → 3개 업체의 가격과 QC 포함 사용 가능일 비교 → `대안 검토` → “추천 업체가 너무 비싼데 더 저렴한 방법은 없어?” 선택. 72만원 절감 분할 대안과 안전재고 부족의 상충 관계를 설명합니다.
4. **가상 승인 (20초)** — `발주 승인` → 상세 확인 → `가상 발주 승인`. 발주 내역에 PO-DEMO-001이 기록되며, 재고는 실제 입고 전까지 18 mg으로 유지됩니다.
5. **변화 대응 (약 1분)** — 추천서 하단 `시나리오 02 시작` 또는 협의실 `공급망 위험 시뮬레이션`. 정전 이벤트를 발생시키고 재협의합니다. B안의 사용일이 11.09로 늦어져 C안으로 바뀝니다. 시간이 부족하면 `결과까지 건너뛰기`를 사용합니다.
6. **수정 승인 (30초)** — C안 추천서의 변경 전·후와 +36만원 확인 → 승인. 기존 B안은 가상 취소, C안은 새 발주 PO-DEMO-002로 기록됩니다.
7. **반복 시연** — `데모 설정 → 초기화 → 전체 데모 초기화`. 원료와 최초 발주 3건, 사고 미발생 상태로 복원합니다.

대시보드 또는 설정의 `자동 시연`은 AI 협의를 재생한 뒤 최종 추천서로 이동합니다. **발주 승인은 자동화하지 않고 담당자에게 남겨 둡니다.** 재생·일시정지·이어 재생·다시 실행·건너뛰기를 지원합니다. `다시 준비`는 협의만, `전체 데모 초기화`는 사고와 승인 이력까지 초기화합니다.

## 화면과 동작

- 대시보드: 위험 인사이트, 4개 KPI, 재고 추이, 주의 원료, 알림과 활동
- AI 협의실: 6개 Agent, 진행 상태, 데이터 전달 애니메이션, 충돌/수정 기록, 최종 판단, 재생 제어
- 발주 추천서: 후보 비교, 비용 막대, 예산, 입고/QC/생산 타임라인, 잔여 위험, 가상 승인, 대안 질문
- 원료·재고: 12종, 검색과 위험도 필터, Lot별 재고/단가/유효기간/보관/QC 상세
- 공급업체: 6개 가상 업체, 승인·납품률·조달기간, 사고 강조
- 생산계획: 4개 Batch와 확보 마감
- 발주 내역: 최초 이력 3건, 승인·취소 반영, UTF-8 BOM CSV 내보내기
- 데모 설정: 속도, 자동 시연, 전체 화면, 초기화, 실제 API 미연결 안내

브라우저 localStorage에 가상 주문 및 사고 상태만 저장합니다. 새로고침 후에도 유지되며, 협의 재생 진행상황과 질문은 세션 내 상태입니다. 브라우저 저장소를 사용할 수 없으면 현재 세션 내 데모는 계속 동작합니다.

## 데이터와 계산의 기준

기준일은 발표 재현성을 위해 **2026-10-24**로 고정합니다. 현지 시간과 무관하게 UTC 날짜 연산을 사용합니다. 모든 소요기간은 영업일이 아닌 **달력일**입니다.

- `src/demo-data.json`: 가상 원료 12종, 공급업체 6곳, 생산계획 4건, 발주 이력 3건, 예산·가정 메타데이터
- 재고 커버리지 = `floor(현재 재고 / 일평균 사용량)`
- 예상 소진일 = 기준일 + 커버리지. 일평균 사용량 기반의 요약 예측이며, 상세 MRP는 아닙니다.
- 재고 위험: 7일 이하 `위험`, 14일 이하 `주의`, 그 외 `안정`
- 사용 가능일 = 기준일 + 조달기간 + 사고 지연 + 입고 QC 기간
- 확보 마감 = 생산 시작 하루 전. FGF-2 Batch 024는 11.02 시작, 11.01 마감입니다.
- 후보 선정 = 공급업체 품질 승인 및 사용 가능일 ≤ 마감인 후보 중 총 비용 최소
- 공급업체 페이지의 가격 데이터는 **FGF-2 견적**이며, 다른 원료 단가는 원료별 기준 단가입니다.

| FGF-2 60 mg | 단가/mg | 조달 + QC | 사용 가능일 | 금액 | 판단 |
|---|---:|---:|---|---:|---|
| A 셀리온 바이오 | 98,000원 | 12+2일 | 11.07 | 5,880,000원 | 마감 6일 초과 |
| B 바이오넥스 | 118,000원 | 4+2일 | 10.30 | 7,080,000원 | 정상 시 최종 추천 |
| C 노바셀 사이언스 | 124,000원 | 5+2일 | 10.31 | 7,440,000원 | 사고 시 최종 추천 |

가상 정전은 B 조달기간에 10일을 더합니다. C안은 11.02 생산 시작 조건을 충족하지만 **기존 재고 소진 10.30~C안 사용 가능 10.31의 1일 공백**이 있으므로 선행 작업 조정이 필요하다는 잔여 위험을 표시합니다. 공급업체 승인과 개별 입고 Lot의 QC 적합 판정은 별개입니다.

분할 대안: B 24 mg + A 36 mg = 636만원, B 단일안 대비 72만원 절감. B 긴급 물량은 10.30~11.06의 8일분(24/3)을 충당하고 A 물량은 11.07 사용 가능합니다. 안전재고 여유가 없어 생산팀 검토가 필요한 **설명용 대안**이며, MVP의 승인 기능은 최종 단일안만 지원합니다.

시나리오 예산 900만원 및 생산 지연 손실 1,800만원은 **시연 가정**입니다. 이 수치는 실제 사업·제품·의학적 판단에 사용할 수 없습니다. 모든 원료 보관 조건과 유효기간은 데모용 Lot 설정이며, 실제 제품군의 일반 사양이 아닙니다.

## 구조와 기술

React + TypeScript + Vite, Tailwind CSS 4, shadcn/ui 방식의 CVA Button 및 Radix Dialog, Lucide Icons, Recharts, Framer Motion, Vitest를 사용합니다. 공통 버튼은 프로젝트에 포함된 소스형 컴포넌트이며 Dialog는 키보드 포커스 제한과 Escape 닫기를 지원합니다. 반응형 레이아웃 및 동작 줄이기 설정을 적용했습니다.

```text
src/
  App.tsx                  화면·재생·승인·로컬 상태
  styles.css               반응형 B2B SaaS 디자인
  demo-data.json           원본 가상 ERP 데이터
  data.ts                  타입·포맷·재고/날짜 계산
  engine.ts                견적·후보 선정·협의 시나리오·서버 어댑터
  engine.test.ts           데이터/발주 결정 검증
  components/ui/button.tsx CVA 기반 재사용 버튼
```

## 실제 OpenAI API 연결을 위한 경계

이 MVP는 **실제 API를 연결하지 않습니다**. `engine.ts`의 `AnalysisProvider` 인터페이스와 `ServerAnalysisProvider`를 확장 지점으로 제공합니다. 화면에 라이브 실행을 가장하는 토글은 두지 않았습니다.

1. 별도 서버에 `POST /api/analysis`를 구현합니다. 요청은 `{question, context}`, 응답은 `{answer: string}`입니다.
2. 서버 환경변수에 `OPENAI_API_KEY`를 보관합니다. `VITE_*` 변수나 브라우저에 키를 넣지 마세요.
3. 서버에서 OpenAI 호출, 타임아웃·오류 처리, 컨텍스트 크기 제한을 구현합니다. 모델명은 배포 시 공식 문서에서 확인합니다.
4. `ServerAnalysisProvider.ask()`에 정제된 ERP 컨텍스트를 전달하도록 Q&A 핸들러를 변경합니다. 연결 성공 시 화면에 `실제 AI 응답`과 모델 호출 상태를 명확히 표시하세요.
5. 발주 결정 계산은 `recommendation()`으로 독립 검증하고, 모델의 설명만으로 재고·주문을 변경하지 않도록 유지합니다.

실제 API 서버, 자유 질문, 실시간 외부 뉴스 수집, ERP 인증, 데이터베이스 및 실제 구매 기능은 구현 범위에서 제외했습니다.
